## 📋 问题概述

### 当前状况
敌人系统无法在多角色游戏中正常工作，表现为：
- 敌人在回合中不执行任何行为
- 敌人找不到攻击目标
- 日志显示"未找到玩家"警告

### 根本原因
代码仍然使用单角色时代的玩家查找逻辑：
- 使用 `FindGameObjectWithTag("Player")` 查找单个玩家
- 只在游戏开始时查找一次
- 不检查玩家是否存活
- 无法适应多个玩家角色的场景

---

## 🎯 目标与原则

### 改造目标
1. **动态目标选择**：敌人每次行动前选择最近的存活玩家
2. **智能切换**：玩家死亡或移动后自动更新目标
3. **容错处理**：所有玩家死亡时优雅停止行为
4. **最小侵入**：只修改目标查找逻辑，不改变行为接口

### 设计原则
- **就近原则**：总是选择距离最近的存活玩家
- **实时更新**：每个行动阶段前重新查找目标
- **解耦设计**：行为组件不感知多玩家，保持接口不变

---

## 🔧 实施方案

### 方案概述
**集中式目标管理**：在 `EnemyBehavior` 中统一处理目标查找，行为组件继续使用单个玩家引用。

### 修改点分布

#### 修改点1：新增目标查找方法
**位置**：`EnemyBehavior.cs`  
**功能**：
- 从 `GameSession.TeamData` 获取所有角色
- 筛选出存活的角色
- 计算距离，返回最近的角色 Transform
- 如果无存活角色，返回 null

**输入**：无（使用敌人自身 Transform）  
**输出**：`Transform`（最近玩家）或 `null`（无存活玩家）

---

#### 修改点2：移除静态玩家查找
**位置**：`EnemyBehavior.Start()`  
**改动**：
- 删除 `FindGameObjectWithTag("Player")` 调用
- 删除 `player` 的静态赋值
- 添加注释说明新的动态查找机制

**理由**：静态查找已过时，改为每阶段动态查找

---

#### 修改点3：预告阶段添加目标更新
**位置**：`ExecuteTelegraphPhase()`  
**改动**：
- 方法开始时调用目标查找
- 检查目标是否为空
- 如果为空，记录警告并提前返回
- 如果不为空，继续原有预告逻辑

**效果**：确保预告总是指向最近的存活玩家

---

#### 修改点4：攻击阶段添加目标更新
**位置**：`ExecuteAttackPhase()`  
**改动**：
- 方法开始时调用目标查找
- 检查目标是否为空
- 如果为空，记录警告并提前返回
- 如果不为空，继续原有攻击逻辑

**效果**：确保攻击总是针对最近的存活玩家

---

#### 修改点5：移动阶段添加目标更新
**位置**：`ExecuteMovePhase()`  
**改动**：
- 方法开始时调用目标查找
- 检查目标是否为空
- 如果为空，记录警告并提前返回
- 如果不为空，继续原有移动逻辑

**效果**：确保移动总是朝向最近的存活玩家

## 📊 执行流程对比

### 改造前（单角色系统）
```
游戏开始
  ↓
Start(): 查找单个玩家 Tag
  ↓
player = 固定引用
  ↓
敌人回合
  ├─ 预告阶段：使用固定 player
  ├─ 攻击阶段：使用固定 player
  └─ 移动阶段：使用固定 player
```

### 改造后（多角色系统）
```
游戏开始
  ↓
Start(): 不查找玩家
  ↓
敌人回合
  ├─ 预告阶段
  │   ├─ FindNearestPlayer() ← 动态查找
  │   ├─ 检查是否为 null
  │   └─ 执行预告（或跳过）
  │
  ├─ 攻击阶段
  │   ├─ FindNearestPlayer() ← 重新查找
  │   ├─ 检查是否为 null
  │   └─ 执行攻击（或跳过）
  │
  └─ 移动阶段
      ├─ FindNearestPlayer() ← 重新查找
      ├─ 检查是否为 null
      └─ 执行移动（或跳过）
```

## 🔄 场景示例

### 场景1：多个存活玩家
```
初始状态：
  - 角色1 在 (-5, 0)，存活
  - 角色2 在 (0, 0)，存活
  - 角色3 在 (5, 0)，存活
  - 敌人 在 (0, 3)

敌人预告阶段：
  → 计算距离：角色1=5.83, 角色2=3.0, 角色3=5.83
  → 选择角色2（最近）
  → 显示指向角色2的攻击预告

敌人攻击阶段：
  → 重新计算距离（角色可能已移动）
  → 选择最近角色
  → 攻击该角色

敌人移动阶段：
  → 重新计算距离
  → 向最近角色移动
```

### 场景2：玩家死亡
```
初始状态：
  - 角色1 死亡
  - 角色2 在 (0, 0)，存活
  - 角色3 在 (5, 0)，存活
  - 敌人 在 (0, 3)

敌人行动：
  → FindNearestPlayer() 跳过角色1（已死亡）
  → 只考虑角色2和角色3
  → 选择最近的存活角色
  → 执行行为
```

### 场景3：全灭
```
初始状态：
  - 所有角色死亡
  - 敌人 在 (0, 3)

敌人行动：
  → FindNearestPlayer() 返回 null
  → 预告阶段：检测到 null，跳过
  → 攻击阶段：检测到 null，跳过
  → 移动阶段：检测到 null，跳过
  → 敌人停止行为，等待游戏结束
```

## ⚠️ 边界情况处理

### 1. 无存活玩家
**检测**：`FindNearestPlayer()` 返回 null  
**处理**：各阶段方法检测到 null 后提前返回  
**日志**：记录警告"找不到存活的玩家"

### 2. 距离相同的多个玩家
**检测**：多个玩家与敌人距离相等  
**处理**：选择遍历时第一个遇到的（由 TeamData 顺序决定）  
**影响**：微小的随机性，可接受

### 3. 玩家在阶段间移动
**检测**：自动检测（每阶段重新查找）  
**处理**：自然切换到移动后最近的玩家  
**效果**：敌人行为更真实，追击移动目标

### 4. TeamData 未初始化
**检测**：`GameSession.Instance?.GetTeamData()` 返回 null  
**处理**：`FindNearestPlayer()` 返回 null  
**效果**：敌人不执行行为，记录错误日志
