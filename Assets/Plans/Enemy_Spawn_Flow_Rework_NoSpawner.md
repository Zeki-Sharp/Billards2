# 敌人生成流程重构（去掉 Spawner/Preview，回合开始前生成）

## 目的与范围
- 目的：
  - 将敌人“生成”从敌人回合子阶段中剥离，迁移到“敌人回合开始前”执行。
  - 废除预告用的 Spawn/Preview 流程，明确“无预告不攻击”的规则。
  - 简化为单一敌人列表的管理模型，减少阶段间移动与状态同步。
- 范围：顶层流程与敌人阶段控制、敌人管理、波次生成触发、Prefab 与配置、事件/可视化联动。

## 核心设计要点
- 阶段顺序调整：敌人子阶段改为「Attack → Move → Telegraph」，不再包含 Spawn。
- 生成时机：在“切换到敌人回合”之前一次性生成当回合需要的新敌人。
- 列表模型：只保留“激活敌人列表”，不再维护“预告中敌人列表”。
- 行为规则：
  - 无预告不攻击；新生成的敌人首回合不会攻击。
  - Telegraph 每回合执行一次，仅用于更新下一回合的攻击范围/方向（可视化可选）。
- 资产规则：Prefab 中 `enemyItem` 默认激活，`spawnPreview` 不再参与显示（后续可清理）。

## 敌人回合三段式
- 回合前（Before Enemy Turn）：切入敌人回合前的一次性任务（生成当回合需要的新敌人、推进波次索引、注册到激活列表）。
- 回合中（During Enemy Turn）：按子阶段顺序执行「Attack → Move → Telegraph」。其中 Telegraph 仅写入下一回合攻击所需数据（可选显示范围提示）。
- 回合后（After Enemy Turn）：回到玩家回合，无 Spawn/预告列表的额外处理。

## 影响评估（高层）
- 顶层回合切换不受影响；子阶段减少为 3 个，去除一次空等待。
- 新敌人首回合仅参与 Telegraph，不参与 Attack；从第二回合起正常攻击。
- 波次推进与生成需从旧触发点迁移到“回合开始前”的统一入口。

## 执行步骤（建议实施顺序）
1) 顶层流程与阶段顺序（过渡安全版）
   - 将敌人阶段顺序由「Attack → Move → Spawn → Telegraph」调整为「Attack → Move → Telegraph」。
   - 过渡策略：为避免旧逻辑中“Telegraphing → Spawn → Active”的转移断层，在 Telegraph 阶段末尾临时完成“首次出现转激活与列表转移”（等价于在同一回合末执行 Spawn 的效果，但不保留 Spawn 子阶段）。
   - 确保阶段推进的节奏（定时或事件）不再对 Spawn 做等待。

2) 生成时机迁移
   - 在enemyphasestart：生成本回合需要的新敌人。
   - 生成完成后，直接登记到“激活敌人列表”，不再进入“预告中”列表。
   - 同步迁移“推进波次索引/状态”的逻辑到此处，避免旧触发点遗漏或重复推进。

3) 列表与管理策略
   - 删除“预告中敌人列表”相关的增删与转移逻辑（Register/Transfer）。
   - 所有阶段（Attack/Move/Telegraph）统一遍历“激活敌人列表”。

4) Telegraph 职责收敛
   - Telegraph 仅负责更新并（可选）显示下一回合的攻击范围/方向。
   - 若全局取消可视化，保持数据更新；若需要提示，维持范围可视化组件的显隐即可。

5) 行为与数据一致性
   - 各攻击行为应在未检测到“已预告数据”时不执行攻击（快速 return）。
   - 新生成敌人首回合不攻击，符合“无预告不攻击”的全局规则。

6) 资产与编辑器配置
   - 敌人 Prefab：`enemyItem` 处于激活，`spawnPreview` 不再参与可见性控制。
   - 场景/关卡配置：原先依赖 Spawner/Preview 的对象与引用逐步移除或替换。

7) 事件与系统联动
   - 如有监听 Spawn/Telegraph 事件做特效/音频，统一迁移到“回合开始前生成完成”或 Telegraph 开始事件。
   - 确保 UI/提示层与“无预告不攻击”规则一致。

8) 清理与兼容
   - 移除与 Spawn 阶段、预告列表、Preview 物体强耦合的冗余接口与日志。
   - 若临时保留旧组件（如 Wave/Spawner），保证其成为“回合开始前生成”的纯数据/执行入口；最终阶段再删除旧文件。

## 验收标准
- 流程：玩家回合结束 → 敌人回合开始前生成 → 敌人回合执行「Attack → Move → Telegraph」→ 回到玩家回合。
- 首回合刚生成的敌人：不攻击，仅在回合末 Telegraph 成功写入下一回合的攻击数据。
- 无异常报错（不再出现“缺少 Spawner/Trigger”的报错）；阶段推进无空等待。
- 仅维护一个敌人列表，Attack/Move/Telegraph 均以此列表为准。

## 风险与缓解
- 风险：遗留代码仍依赖“预告列表”或 Spawn 事件。
  - 缓解：灰度删除；先让旧接口成为 no-op，再集中删除。
- 风险：个别攻击行为在无 Telegraph 数据时仍尝试攻击。
  - 缓解：在行为层增加轻量校验（无预告数据则 return），并做用例回归。
- 风险：波次推进时机遗漏或重复。
  - 缓解：把推进逻辑固定在“回合开始前生成”的同一入口，统一管理状态。

## 发布与回滚
- 发布：
  - 先切阶段顺序 → 迁移生成入口与波次推进 → 列表/接口收敛 → 资产与事件同步 → 清理冗余。
  - 每步后做快速回归（生成/攻击/移动/Telegraph 的最小用例）。
- 回滚：
  - 保留切换前的分支；若出现严重问题，恢复到包含 Spawn/Telegraphing 列表的旧实现。

## 后续可选优化（不阻塞本次变更）
- 根据关卡节奏调整敌人阶段的时间间隔/播放速度。
- 统一把“生成入口 + 波次推进”抽象为独立的“回合开始前任务管线”，便于未来扩展（如道具刷新、环境事件）。
