# 事件优先级系统实施方案1 - 计划文档

## 📋 项目概述

**目标**：将现有的 `GameEventBus` 事件系统升级为基于委托链的优先级系统，确保弱点判定在伤害应用之前执行。

**核心问题**：当前 `OnAttack` 事件的订阅者执行顺序不确定，导致 `WeakPointManager` 的伤害修改可能无效。

## 🎯 实施目标

1. **解决执行顺序问题**：确保弱点判定（高优先级）在伤害应用（低优先级）之前执行
2. **建立通用优先级系统**：为未来更多事件提供优先级管理能力
3. **保持向后兼容**：现有事件订阅者能够平滑迁移
4. **性能优化**：最小化优先级系统带来的性能开销

## 📊 修改范围分析

### 核心文件修改
- **`GameEventBus.cs`**：核心重构，添加优先级系统
- **`WeakPointManager.cs`**：修改订阅方式，使用高优先级
- **`EnemyBehavior.cs`**：修改订阅方式，使用低优先级
- **其他 `OnAttack` 订阅者**：需要识别并修改

### 影响评估
- **高风险**：`GameEventBus.cs` 核心架构修改
- **中风险**：所有事件订阅者的订阅方式修改
- **低风险**：事件发布者的调用方式修改

## 🔧 技术方案设计

### 1. 优先级枚举定义
- **Critical**：关键优先级（系统级）
- **High**：高优先级（弱点判定、状态检查）
- **Normal**：普通优先级（默认）
- **Low**：低优先级（伤害应用、UI更新）
- **Background**：后台优先级（日志、统计）

### 2. 数据结构设计
- 使用 `Dictionary<EventPriority, List<Action<AttackData>>>` 存储不同优先级的事件处理器
- 提供初始化方法确保所有优先级都有对应的列表
- 支持动态添加和移除处理器

### 3. 订阅/取消订阅接口
- 带优先级的订阅方法：`SubscribeAttack(EventPriority priority, Action<AttackData> handler)`
- 带优先级的取消订阅方法：`UnsubscribeAttack(EventPriority priority, Action<AttackData> handler)`
- 向后兼容的订阅方法（默认Normal优先级）

### 4. 事件发布逻辑
- 按优先级顺序遍历所有优先级
- 在每个优先级内按顺序执行所有处理器
- 包含完善的异常处理机制
- 提供详细的调试日志

## 🚨 风险评估与应对

### 高风险项目

#### 1. `GameEventBus.cs` 核心修改
**风险**：可能破坏现有事件系统
**应对**：
- 保持向后兼容的订阅方法
- 分阶段测试，确保每个修改都经过验证
- 准备回滚方案

#### 2. 事件订阅者修改
**风险**：可能遗漏某些订阅者，导致功能异常
**应对**：
- 使用代码搜索工具全面识别所有订阅者
- 创建详细的迁移清单
- 逐个验证每个订阅者的修改

### 中风险项目

#### 1. 性能影响
**风险**：优先级系统可能带来性能开销
**应对**：
- 进行性能基准测试
- 优化数据结构访问方式
- 考虑缓存优化

#### 2. 错误处理
**风险**：事件处理器异常可能影响其他处理器
**应对**：
- 实现完善的异常处理机制
- 添加详细的错误日志
- 测试异常场景
