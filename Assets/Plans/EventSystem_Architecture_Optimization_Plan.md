# 事件系统架构优化方案

## 文档信息
- **创建日期**: 2024年12月
- **版本**: 1.0
- **状态**: 规划阶段
- **优先级**: 高
- **最后更新**: 2024年12月

## 概述

本文档分析当前事件系统的组件定位，提出统一事件总线的优化方案，解决事件系统混乱、职责不清的问题。

## 当前事件系统组件分析

### 现有组件定位

#### 1. MMEventManager (MoreMountains)
- **定位**: 底层事件分发引擎
- **职责**: 事件分发、订阅管理、事件触发
- **特点**: 第三方库，基于 struct 事件
- **使用场景**: 特效系统、状态机通信

#### 2. EventTrigger (已删除)
- **定位**: ~~游戏逻辑事件触发接口~~ (已废弃)
- **职责**: ~~提供 C# Action 事件、桥接游戏逻辑和表现~~ (已迁移到 GameEventBus)
- **问题**: ~~职责混乱，既处理逻辑又处理特效~~ (已解决)
- **使用场景**: ~~攻击事件、死亡事件、特效触发~~ (已统一)

#### 3. GameEvents.cs
- **定位**: 事件数据结构定义
- **职责**: 定义事件结构体、提供事件触发方法
- **问题**: ~~与 EventTrigger 职责重叠~~ (已解决)
- **使用场景**: 攻击数据、死亡数据、特效事件

#### 4. EffectManager
- **定位**: 特效事件处理器
- **职责**: 监听 MMEventManager 事件、分发特效
- **特点**: 单例模式，实现 MMEventListener 接口
- **使用场景**: 特效播放、音效管理

#### 5. 组件级事件
- **定位**: 分散的事件定义
- **职责**: 各组件内部的事件通信
- **问题**: 事件分散、命名不统一
- **使用场景**: 蓄力系统、瞄准线、玩家状态

### 当前架构问题

#### 1. 职责混乱 (已解决)
- ~~EventTrigger 既处理游戏逻辑又处理特效~~ (已统一到 GameEventBus)
- ~~GameEvents 和 EventTrigger 功能重叠~~ (已分离)
- ~~组件级事件分散管理~~ (已集中到 GameEventBus)

#### 2. 事件系统分散 (已解决)
- MMEventManager (struct 事件) - 保留
- ~~EventTrigger (C# Action 事件)~~ (已删除)
- ~~组件级事件 (直接 Action)~~ (已统一到 GameEventBus)
- 缺少统一管理

#### 3. 使用方式不一致 (已解决)
- ~~有些用 `EventTrigger.OnAttack`~~ (已统一到 GameEventBus.OnAttack)
- ~~有些用 `EffectEvent.Trigger`~~ (已统一到 GameEventBus.PublishEffectEvent)
- ~~有些用组件级 `OnChargingProgressChanged`~~ (已统一到 GameEventBus.OnChargingProgressChanged)
- ~~缺少统一规范~~ (已建立统一规范)

#### 4. 维护困难 (已解决)
- ~~事件定义分散在多个文件~~ (已集中到 GameEventBus)
- ~~订阅管理不统一~~ (已统一管理)
- ~~难以追踪事件流~~ (已建立统一事件流)

## 优化方案

### 方案选择：统一事件总线架构

#### 核心思想
- **GameEventBus**: 统一的事件接口层
- **MMEventManager**: 底层事件分发引擎
- **GameEvents**: 纯数据结构定义
- **EffectManager**: 特效事件处理器

### 目标架构

```
┌─────────────────────────────────────────────────────────────┐
│                    GameEventBus (统一接口)                    │
├─────────────────────────────────────────────────────────────┤
│  • 统一的事件订阅接口 (C# Action)                            │
│  • 统一的事件发布方法                                        │
│  • 封装游戏逻辑和表现的桥接                                  │
│  • 集成 MMEventManager 调用                                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   GameEvents.cs (数据结构)                   │
├─────────────────────────────────────────────────────────────┤
│  • 事件数据结构定义 (AttackData, DeathData 等)              │
│  • 事件触发方法 (EffectEvent.Trigger 等)                    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                 MMEventManager (底层实现)                    │
├─────────────────────────────────────────────────────────────┤
│  • 事件分发和监听                                            │
│  • 维护订阅者列表                                            │
│  • 调用订阅者的处理方法                                      │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                 EffectManager (事件处理)                     │
├─────────────────────────────────────────────────────────────┤
│  • 实现 MMEventListener 接口                                │
│  • 在 OnMMEvent 中处理事件                                  │
│  • 分发给具体的特效播放器                                    │
└─────────────────────────────────────────────────────────────┘
```

### 组件重新定位

#### 1. GameEventBus (新增)
- **定位**: 统一事件接口层
- **职责**: 
  - 提供统一的事件订阅接口
  - 提供统一的事件发布方法
  - 封装游戏逻辑和表现的桥接
  - 集成 MMEventManager 调用
- **特点**: 静态类，单例模式
- **使用场景**: 所有游戏事件的总入口

#### 2. MMEventManager (保持)
- **定位**: 底层事件分发引擎
- **职责**: 事件分发、订阅管理、事件触发
- **特点**: 第三方库，基于 struct 事件
- **使用场景**: 特效系统、状态机通信

#### 3. GameEvents.cs (重构)
- **定位**: 纯数据结构定义
- **职责**: 定义事件结构体、提供事件触发方法
- **特点**: 移除与 EventTrigger 重叠的功能
- **使用场景**: 事件数据结构定义

#### 4. EffectManager (保持)
- **定位**: 特效事件处理器
- **职责**: 监听 MMEventManager 事件、分发特效
- **特点**: 单例模式，实现 MMEventListener 接口
- **使用场景**: 特效播放、音效管理

#### 5. EventTrigger (废弃)
- **定位**: 逐步废弃
- **职责**: 功能迁移到 GameEventBus
- **特点**: 保持向后兼容，逐步移除
- **使用场景**: 过渡期间保持兼容

### 事件分类和迁移

#### 1. 游戏逻辑事件 (C# Action)
- **当前**: EventTrigger.OnAttack, EventTrigger.OnDeath
- **目标**: GameEventBus.OnAttack, GameEventBus.OnDeath
- **特点**: 直接调用，用于游戏逻辑处理

#### 2. 表现事件 (Struct + MMEventManager)
- **当前**: EffectEvent, AttackEffectEvent, DeathEffectEvent
- **目标**: 通过 GameEventBus 封装调用
- **特点**: 通过 MMEventManager 分发，用于特效播放

#### 3. 组件级事件 (C# Action)
- **当前**: OnChargingProgressChanged, OnLaunch 等
- **目标**: 迁移到 GameEventBus
- **特点**: 统一管理，避免分散

### 实施计划

#### 阶段1: 创建 GameEventBus (1-2天)
1. **创建 GameEventBus 类**
   - 定义统一的事件订阅接口
   - 封装现有 EventTrigger 功能
   - 集成 MMEventManager 调用

2. **保持向后兼容**
   - EventTrigger 作为 GameEventBus 的包装
   - 现有代码无需修改
   - 逐步迁移到新接口

#### 阶段2: 迁移组件级事件 (2-3天)
1. **迁移蓄力系统事件**
   - OnChargingProgressChanged → GameEventBus.OnChargingProgressChanged
   - OnForceChanged → GameEventBus.OnForceChanged
   - OnChargingStarted → GameEventBus.OnChargingStarted

2. **迁移瞄准线事件**
   - OnLaunch → GameEventBus.OnLaunch
   - OnAimDirectionChanged → GameEventBus.OnAimDirectionChanged
   - OnAimVisibilityChanged → GameEventBus.OnAimVisibilityChanged

3. **更新组件代码**
   - 修改 ChargeSystem 事件发布
   - 修改 AimController 事件订阅
   - 更新相关组件

#### 阶段3: 重构 GameEvents.cs (1-2天)
1. **移除重叠功能**
   - 移除与 EventTrigger 重叠的触发方法
   - 保留纯数据结构定义
   - 简化事件结构

2. **优化事件定义**
   - 统一事件命名规范
   - 优化事件数据结构
   - 添加事件文档

#### 阶段4: 废弃 EventTrigger (1-2天)
1. **标记废弃**
   - 添加 [Obsolete] 标记
   - 更新相关文档
   - 提供迁移指南

2. **完全移除**
   - 移除 EventTrigger 类
   - 更新所有调用点
   - 清理相关代码

#### 阶段5: 优化和测试 (1-2天)
1. **性能优化**
   - 优化事件分发性能
   - 减少不必要的事件创建
   - 添加事件缓存机制

2. **测试验证**
   - 功能测试
   - 性能测试
   - 兼容性测试

### 预期效果

#### 代码质量提升
- **统一性**: 所有事件通过 GameEventBus 处理
- **可维护性**: 事件逻辑集中管理
- **可扩展性**: 易于添加新事件类型
- **类型安全**: 编译时检查

#### 性能优化
- **减少重复**: 避免多重封装
- **优化分发**: 统一事件分发机制
- **内存管理**: 更好的事件生命周期管理

#### 开发效率
- **学习成本**: 统一的事件使用方式
- **调试便利**: 集中的事件日志
- **文档清晰**: 统一的事件文档

### 风险评估

#### 技术风险
- **兼容性**: 现有代码需要修改
- **性能**: 可能影响事件分发性能
- **复杂度**: 增加系统复杂度

#### 缓解措施
- **渐进式迁移**: 分阶段实施
- **向后兼容**: 保持现有 API
- **充分测试**: 每个阶段都进行测试

### 总结

通过引入 GameEventBus 作为统一事件接口层，可以解决当前事件系统混乱、职责不清的问题。这个方案既保持了现有系统的稳定性，又提供了统一的事件管理机制，为未来的功能扩展奠定了良好的基础。

建议优先实施阶段1和阶段2，这两项改进将带来最大的收益。后续的阶段可以根据实际需要进行调整。
