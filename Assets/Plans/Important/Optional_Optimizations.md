# 可选优化功能清单

> 记录"有则更好，无也不影响"的优化项，按优先级排序

## 📋 文档规范

### 功能记录格式
每个优化项应包含以下内容，保持简洁（总字数 ≤ 300字）：

```markdown
### N. 优化标题（简短） ⭐⭐⭐

**功能**：1-2句话说明优化内容  
**收益**：提升什么方面的体验或性能  
**成本**：预计工时 + 实施难度  
**时机**：建议实施的时间点
```

### 优先级定义
- **⭐⭐⭐** - 高价值：收益明显，成本适中，建议优先实施
- **⭐⭐** - 中价值：有一定收益，成本较高或收益有限
- **⭐** - 低价值：锦上添花，可做可不做

### 管理规则
1. **新增优化**：找到正确的优先级位置插入
2. **优化完成**：立即从文档删除
3. **优先级调整**：根据项目需求动态调整
4. **保持精简**：每个优化描述控制在 10 行以内

### ⚠️ 新增条目检查清单
添加新优化时，必须按以下步骤操作：
- [ ] 1. 评估优先级（⭐⭐⭐ / ⭐⭐ / ⭐）
- [ ] 2. 找到同优先级组的最后一个条目
- [ ] 3. 在其后插入新条目
- [ ] 4. 更新编号（确保 1, 2, 3... 连续）
- [ ] 5. 更新其他文档中的引用编号

## 🚀 可选优化项（按优先级排序）

### 1. Table 抽象系统（成长曲线） ⭐⭐⭐

**功能**：通用数值表系统，支持线性/指数/手动配置的成长曲线，用于技能升级、敌人成长等。  
**收益**：数值设计更灵活，易于平衡调整，减少硬编码。支持复杂成长曲线（如指数增长、S型曲线）。  
**成本**：2-3天，难度低。需创建 `ITable` 接口和 3+ 种实现（TableLinear、TableGeometric、TableManual）。  
**时机**：当数值配置变复杂或需要快速调整平衡时实施。当前手动配置可接受。

---

### 2. Override 机制（实例微调） ⭐⭐⭐

**功能**：支持在不修改配置的情况下，对单个实例进行数值微调（如特殊敌人血量+50%）。  
**收益**：配置更灵活，支持特殊关卡设计，无需创建新配置。  
**成本**：1-2天，难度低。需创建 Override 配置类和应用逻辑。  
**时机**：当需要大量"同类型但数值略有差异"的实例时。当前多等级配置已足够。

---

### 3. Memory Token 存档系统 ⭐⭐

**功能**：统一的存档架构，分离存档数据（Token）和运行时对象，支持快照和恢复。  
**收益**：统一存档接口，易于扩展，便于实现回放等功能，方便调试状态保存。  
**成本**：3-4天，难度中。需创建 Token/Memory 基类和序列化逻辑。  
**时机**：当需要完整存读档或状态快照功能时。当前 GameSession 已满足基本需求。

---

### 4. Repository 模式（配置查找优化） ⭐⭐

**功能**：创建配置仓库（SkillRepository、EnemyRepository），构建缓存字典，优化查找性能（O(n) → O(1)）。  
**收益**：提升配置查找性能，代码更清晰，统一配置管理入口。  
**成本**：1-2天，难度低。需创建 Repository ScriptableObject 和缓存逻辑。  
**时机**：当技能/敌人配置数量 > 50 且查找成为性能瓶颈时。

---

### 5. 事件优先级系统 ⭐⭐

**功能**：为 GameEventBus 添加优先级机制，控制多个监听器的执行顺序，支持事件拦截。  
**收益**：精确控制事件执行顺序，支持复杂交互逻辑（如"护盾先响应伤害，再扣血"）。  
**成本**：2-3天，难度中。需重构 GameEventBus，改为优先级队列。  
**时机**：当需要精确控制事件执行顺序时。当前执行顺序可预测。

---

### 6. Inspector 调试工具增强 ⭐⭐

**功能**：为配置类添加验证按钮、预览按钮，为 Manager 添加状态查看器、性能分析器。  
**收益**：调试效率提升，配置错误更早发现，运行时状态可视化。  
**成本**：1-2天，难度低。使用 Odin Inspector 快速实现。  
**时机**：贯穿整个开发过程，持续增强。

---

### 7. 异步系统统一化（async/await） ⭐

**功能**：全面采用 `async/await` 模式替代协程，提供统一的异步辅助方法和取消机制。  
**收益**：异步逻辑更清晰，支持取消和异常处理，代码可读性提升。  
**成本**：5-7天，难度中高。需重构大量协程代码，谨慎测试。  
**时机**：当协程复杂度过高或需要高级异步控制时。当前协程够用。

---

### 8. 配置自动迁移工具 ⭐

**功能**：编写编辑器脚本，自动检测并迁移旧配置格式到新格式（如 enum → 多态配置）。  
**收益**：减少手动配置工作，降低迁移错误率。  
**成本**：2-3天，难度中。需解析旧配置并重建新配置，风险较高。  
**时机**：当配置数量 > 20 且格式变化频繁时。当前配置少，手动更快。
