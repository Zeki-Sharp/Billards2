# 待办事项清单

> 记录确定要做但还没来得及做的功能和任务，按优先级排序

## 📋 文档规范

### 任务记录格式
每个任务应包含以下内容，保持简洁（总字数 ≤ 300字）：

```markdown
### N. 任务标题（简短） ⭐⭐⭐

**任务**：1-2句话说明要做什么  
**原因**：为什么要做这个（价值/需求）  
**成本**：预计工时 + 实施难度
```

**注意**：TodoList 中的任务都是"确定要做的"，无需"时机"字段（时机=尽快完成）

### 优先级定义
- **⭐⭐⭐** - 高优先级：核心功能，应尽快完成
- **⭐⭐** - 中优先级：重要功能，可适当排期
- **⭐** - 低优先级：次要功能，有空再做

### 管理规则
1. **新增任务**：找到正确的优先级位置插入
2. **任务完成**：立即从文档删除
3. **优先级调整**：根据项目需求动态调整
4. **保持精简**：每个任务描述控制在 10 行以内

### ⚠️ 新增条目检查清单
添加新任务时，必须按以下步骤操作：
- [ ] 1. 评估优先级（⭐⭐⭐ / ⭐⭐ / ⭐）
- [ ] 2. 找到同优先级组的最后一个条目
- [ ] 3. 在其后插入新条目
- [ ] 4. 更新编号（确保 1, 2, 3... 连续）
- [ ] 5. 更新其他文档中的引用编号

### 1. 回合超时扣血功能多角色适配 ⭐⭐

**任务**：改造 TurnPenaltyManager 适配多角色系统，将 `FindFirstObjectByType<PlayerBehavior>()` 改为按策略惩罚（所有存活角色/当前选中角色/废弃功能）。  
**原因**：当前使用单角色查找逻辑，多角色系统下会错误惩罚或找不到目标，影响游戏机制正确性。  
**成本**：1-2小时，难度低。需先决定惩罚策略，然后实现对应逻辑（遍历队伍或获取选中角色）。

**任务**：实现主动技能支持（玩家按键主动触发），当前所有技能都是被动的（事件驱动）。

**成本**：3-5天，难度中。需添加输入监听、技能槽 UI、冷却系统、可能需要瞄准系统和资源消耗。
