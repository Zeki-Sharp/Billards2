# 技能修改器生命周期重构计划 v2.0

> **文档目的**: 重构技能修改器的生命周期管理，支持双模式：创建/删除模式和启用/禁用模式  
> **创建日期**: 2025-01-21  
> **文档版本**: v2.0

---

## 📋 问题背景

### 当前问题
- **叠加效果失效**: 击杀增加攻击力技能无法产生叠加效果（+5, +10, +15...）
- **状态管理复杂**: 需要跟踪 `isApplied`、`isEnabled`、`appliedModifier` 等多个状态
- **内存积累**: 修改器被禁用但不删除，导致内存浪费
- **调试困难**: 难以跟踪修改器的实际状态
- **模式单一**: 只有一种模式，无法适应不同类型的技能效果

### 根本原因
`StatModifierEffect` 采用单一的"启用/禁用模式"：
- 第1次执行：创建修改器
- 第2次及以后：重新启用现有修改器
- 移除时：只禁用，不删除

### 新发现的问题
经过阶段1重构后，发现**创建/删除模式**不适合所有技能效果：
- ✅ **击杀增加攻击力**：需要叠加效果（+5, +10, +15...）→ 适合创建/删除模式
- ❌ **满血攻击增加**：不需要叠加效果（始终+50%）→ 不适合创建/删除模式

---

## 🎯 设计目标

### 主要目标
1. **支持双模式**: 创建/删除模式 + 启用/禁用模式
2. **配置驱动**: 通过配置选择使用哪种模式
3. **向后兼容**: 现有技能配置无需修改
4. **灵活适配**: 适应不同类型的技能效果需求

### 设计原则
- **模式分离**: 不同模式有不同的实现逻辑
- **配置统一**: 通过统一配置选择模式
- **接口一致**: 保持 `IEffect` 接口不变
- **状态清晰**: 每种模式的状态管理简单明了

---

## 🔄 架构对比

### 当前架构（单一创建/删除模式）

```
技能执行流程:
├─ 击杀增加攻击力 → 创建修改器A (+5) → 叠加效果 ✅
├─ 满血攻击增加 → 创建修改器B (+50%) → 重复创建 ❌
└─ 问题：满血攻击增加不需要叠加，但会重复创建修改器

问题:
- 无法适应非叠加效果
- 可能创建过多修改器
- 内存使用不当
```

### 目标架构（双模式支持）

```
技能执行流程:

创建/删除模式（叠加效果）:
├─ 击杀增加攻击力 → 创建修改器A (+5)
├─ 第2次击杀 → 创建修改器B (+5) → 总效果 +10 ✅
├─ 第3次击杀 → 创建修改器C (+5) → 总效果 +15 ✅
└─ 移除条件满足 → 删除修改器A → 总效果 +10 ✅

启用/禁用模式（非叠加效果）:
├─ 满血攻击增加 → 创建修改器A (+50%)
├─ 第2次满血 → 重新启用修改器A (+50%) → 总效果 +50% ✅
├─ 第3次满血 → 重新启用修改器A (+50%) → 总效果 +50% ✅
└─ 移除条件满足 → 禁用修改器A → 总效果 0% ✅

优势:
- 支持叠加和非叠加效果
- 模式选择灵活
- 内存使用合理
- 状态管理清晰
```

## 🛠️ 实施计划

### 阶段1：双模式架构设计 ✅

#### 1.1 模式枚举定义
**目标**: 定义两种修改器模式

**实现内容**:
- 创建 `ModifierMode` 枚举
- 定义 `CreateDelete` 和 `EnableDisable` 两种模式
- 添加模式说明文档

#### 1.2 StatModifierEffect 双模式支持
**目标**: 在 StatModifierEffect 中支持两种模式

**实现内容**:
- 添加 `modifierMode` 配置字段
- 实现 `ExecuteCreateDeleteMode()` 方法
- 实现 `ExecuteEnableDisableMode()` 方法
- 根据模式选择执行逻辑

#### 1.3 SkillDamageModifier 双模式支持
**目标**: 恢复启用/禁用逻辑，支持两种模式

**实现内容**:
- 恢复 `isEnabled` 状态字段
- 恢复 `SetEnabled()` 方法
- 恢复 `ShouldRemove()` 逻辑
- 支持两种模式的构造函数

### 阶段2：配置系统集成

#### 2.1 效果配置扩展
**目标**: 在效果配置中添加模式选择

**实现内容**:
- 在 `EffectConfig` 中添加 `modifierMode` 字段
- 设置默认值为 `CreateDelete`（保持向后兼容）
- 添加配置验证逻辑

#### 2.2 技能实例模式传递
**目标**: 将配置的模式传递给效果实例

**实现内容**:
- 在 `SkillInstance` 创建时传递模式配置
- 在 `StatModifierEffect` 初始化时设置模式
- 添加模式验证和错误处理

### 阶段3：测试和优化

#### 3.1 功能测试
**目标**: 验证两种模式的功能正确性

**测试内容**:
- 测试击杀增加攻击力（创建/删除模式）
- 测试满血攻击增加（启用/禁用模式）
- 测试模式切换和配置

#### 3.2 性能优化
**目标**: 优化双模式的性能表现

**优化内容**:
- 减少不必要的模式检查
- 优化内存使用
- 添加性能监控

## ⚠️ 风险评估

### 高风险
- **模式切换**: 如果模式切换逻辑有bug，可能导致效果异常
- **配置错误**: 错误的模式配置可能导致技能行为不符合预期

### 中风险
- **性能影响**: 双模式支持可能增加代码复杂度
- **测试覆盖**: 需要测试两种模式的所有场景

### 低风险
- **向后兼容**: 默认模式保持现有行为
- **用户影响**: 对最终用户透明

## 📝 总结

这次重构的核心目标是**支持双模式**，既保持创建/删除模式的优势，又恢复启用/禁用模式的灵活性。

**主要收益**:
1. **功能完整性**: 支持叠加和非叠加两种效果
2. **配置灵活性**: 通过配置选择适合的模式
3. **向后兼容**: 现有技能配置无需修改
4. **架构清晰**: 模式分离，职责明确

**实施重点**:
- 保持 `IEffect` 接口不变
- 通过配置驱动模式选择
- 确保两种模式都能正确工作
- 提供清晰的调试和监控信息

通过这次重构，技能修改器系统将能够适应各种不同类型的技能效果需求。
