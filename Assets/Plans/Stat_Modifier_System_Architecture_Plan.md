# 属性修饰器系统架构设计计划

## 文档信息
- **创建日期**: 2024年12月
- **版本**: 1.0
- **状态**: 设计阶段
- **优先级**: 中
- **最后更新**: 2024年12月

## 概述

设计一个简洁而强大的属性修饰器系统，用于管理游戏中所有动态属性变化。系统遵循最小架构原则，避免过度设计，专注于解决当前技能系统中的属性管理问题。

## 核心设计原则

### 1. 最小架构原则
- 只实现当前需要的功能
- 避免复杂的继承层次
- 保持接口简洁明了
- 优先使用组合而非继承

### 2. 职责分离
- **基础数据层**：PlayerData 只存储基础属性
- **修饰器层**：StatModifier 存储属性变化信息
- **计算层**：PlayerStatsManager 负责最终值计算
- **管理层**：处理修饰器的生命周期

### 3. 扩展性设计
- 支持新属性类型的添加
- 支持新的修饰器类型
- 支持不同的移除条件
- 保持向后兼容性

## 整体架构设计

### 三层架构（最小化设计）

```
┌─────────────────────────────────────────────────────────────┐
│                    属性修饰器系统三层架构                     │
├─────────────────────────────────────────────────────────────┤
│  PlayerData (基础数据层)                                      │
│  ├── 存储基础属性值 (BaseDamage, BaseMaxHealth等)             │
│  ├── 不包含任何动态计算逻辑                                    │
│  └── 作为ScriptableObject配置                                │
├─────────────────────────────────────────────────────────────┤
│  StatModifier (修饰器层)                                      │
│  ├── 存储单个属性修改信息                                      │
│  ├── 包含修改类型、数值、来源、持续时间                        │
│  └── 支持临时效果和永久效果                                    │
├─────────────────────────────────────────────────────────────┤
│  PlayerStatsManager (计算管理层)                              │
│  ├── 管理所有活跃的修饰器                                      │
│  ├── 计算属性的最终值                                          │
│  ├── 处理修饰器的生命周期                                      │
│  └── 提供属性查询接口                                          │
└─────────────────────────────────────────────────────────────┘
```

## 核心组件设计

### 1. StatModifier (属性修饰器)

**职责：**
- 存储单个属性修改的所有信息
- 定义修改的类型和数值
- 记录效果的来源和持续时间
- 支持不同的移除条件

**核心属性：**
- **修改类型**：Add(固定值)、PercentAdd(百分比增加)、PercentMult(百分比乘数)
- **修改数值**：具体的修改值
- **目标属性**：要修改的属性名称
- **效果来源**：产生此修饰器的对象或系统
- **持续时间**：效果的持续时间（0表示永久）
- **移除条件**：效果何时被移除

**设计特点：**
- 轻量级数据结构
- 不可变设计（创建后不修改）
- 支持序列化和调试

### 2. PlayerStatsManager (属性管理器)

**职责：**
- 管理所有活跃的属性修饰器
- 计算属性的最终值
- 处理修饰器的生命周期
- 提供属性查询接口

**核心功能：**
- **修饰器管理**：添加、移除、查询修饰器
- **最终值计算**：基于基础值和所有修饰器计算最终值
- **生命周期管理**：处理有时限的效果
- **事件通知**：属性变化时通知相关系统

**计算规则：**
```
最终值 = (基础值 + 所有固定值) × (1 + 所有百分比增加) × 所有百分比乘数
```

**性能优化：**
- 缓存计算结果
- 按需更新
- 批量处理

### 3. 移除条件系统

**支持的条件类型：**
- **时间条件**：持续X秒后自动移除
- **事件条件**：特定游戏事件发生后移除
- **状态条件**：特定游戏状态改变时移除
- **手动条件**：外部系统手动触发移除

**事件条件示例：**
- OnNextCollisionEnd：下次碰撞结束后移除
- OnNextAttack：下次攻击后移除
- OnHealthBelow：血量低于阈值时移除
- OnBallStopped：球停止运动时移除

## 与现有系统集成

### 1. 与PlayerData集成
- PlayerData 重命名为存储基础属性
- 移除直接修改基础数据的逻辑
- 保持现有配置接口不变

### 2. 与技能系统集成
- StatModifierEffect 使用修饰器系统
- 支持技能的临时效果和永久效果
- 与技能生命周期管理集成

### 3. 与事件系统集成
- 利用现有的GameEventBus
- 支持基于事件的修饰器移除
- 属性变化时触发相关事件

## 使用场景示例

### 1. 技能效果
```
连击技能：攻击力+50%，持续10秒
- 创建PercentAdd修饰器，值=0.5，持续时间=10秒
- 自动在10秒后移除
```

### 2. 临时增益
```
碰撞3次后攻击力+50%，下次攻击后移除
- 创建PercentAdd修饰器，值=0.5，移除条件=OnNextAttack
- 在下次攻击事件时移除
```

### 3. 装备效果
```
武器：攻击力+20点
- 创建Add修饰器，值=20，永久效果
- 装备卸下时移除
```

### 4. 叠加效果
```
基础攻击力20 + 装备+10 + 技能+50% = (20+10)×1.5 = 45
```

## 技术要点

### 性能考虑
- **按需计算**：只在需要时计算最终值
- **缓存机制**：缓存计算结果，避免重复计算
- **批量更新**：合并多个修饰器变化
- **内存管理**：及时清理过期的修饰器

### 扩展性考虑
- **新属性支持**：通过配置添加新属性
- **新修饰器类型**：通过枚举扩展支持新的计算类型
- **新移除条件**：通过事件系统支持新的移除条件
- **插件化设计**：支持外部系统扩展功能

### 调试和维护
- **详细日志**：记录修饰器的应用和移除
- **可视化工具**：显示当前所有活跃的修饰器
- **性能监控**：监控计算性能
- **单元测试**：确保计算逻辑的正确性

## 与技能系统的关系

### 当前问题
- StatModifierEffect 直接修改 PlayerData
- 无法处理临时效果
- 难以管理多个效果的叠加

### 解决方案
- StatModifierEffect 创建修饰器而非直接修改数据
- 通过修饰器系统管理所有属性变化
- 支持复杂的技能效果组合

### 集成方式
```
技能触发 → StatModifierEffect → 创建StatModifier → PlayerStatsManager → 计算最终值
```

## 注意事项

### 1. 向后兼容性
- 保持现有PlayerData接口不变
- 渐进式迁移现有代码
- 确保现有功能不受影响

### 2. 性能影响
- 监控计算性能
- 避免过度复杂的计算逻辑
- 合理使用缓存机制

### 3. 内存管理
- 及时清理过期的修饰器
- 避免修饰器列表无限增长
- 合理使用对象池

### 4. 调试友好
- 提供清晰的日志信息
- 支持可视化调试工具
- 便于问题定位和修复

## 总结

属性修饰器系统是一个简洁而强大的解决方案，专门用于管理游戏中的动态属性变化。通过三层架构设计，系统实现了职责分离、高度灵活和易于扩展的目标。

### 核心优势
- **职责清晰**：基础数据、修饰器、计算逻辑分离
- **高度灵活**：支持各种复杂的属性修改需求
- **易于扩展**：新属性、新修饰器类型、新移除条件
- **性能可控**：按需计算、缓存机制、批量处理
- **调试友好**：详细日志、可视化工具、单元测试

这个系统为技能系统提供了坚实的属性管理基础，支持各种复杂的游戏机制，同时保持了良好的性能和可维护性。
