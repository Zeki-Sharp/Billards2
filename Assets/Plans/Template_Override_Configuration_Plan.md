# 模板+覆盖配置系统优化计划

## 文档信息
- **创建日期**: 2024年12月
- **版本**: 1.0
- **状态**: 设计阶段
- **优先级**: 高
- **目标系统**: 技能系统、敌人系统
- **设计模式**: 模板+增量覆盖模式

---

## 概述

本计划旨在优化技能和敌人系统中的多等级/多层级配置方式，通过引入"模板+覆盖"设计模式，消除大量重复配置，提升配置效率和可维护性。

### 核心问题

**当前架构的痛点**：
- ❌ 每个等级/层级都是完整独立的配置
- ❌ 大量重复配置（触发器、条件、行为等）
- ❌ 修改共享逻辑需要改所有等级
- ❌ 配置量随等级数量线性增长
- ❌ 容易出现配置不一致问题

**目标架构**：
- ✅ 提取共享配置到统一模板
- ✅ 各等级只配置差异部分
- ✅ 修改共享逻辑只需改模板
- ✅ 配置量大幅减少（60-80%）
- ✅ 保证配置一致性

---

## 设计原则

### 1. 分离共享与差异
- **共享配置**：所有等级都相同的部分（触发器、基础行为等）
- **差异配置**：各等级不同的部分（数值、特效、特殊能力等）

### 2. 模板优先
- 优先从模板读取配置
- 覆盖配置只在需要时应用
- 未覆盖的部分自动使用模板

### 3. 增量配置
- 高等级不需要重复配置低等级的内容
- 只配置增量变化
- 支持可选的完全覆盖

### 4. 向后兼容
- 保持现有 API 不变
- 新旧配置方式可以共存
- 提供配置迁移工具

## 核心架构设计

### 三层配置结构

```
┌─────────────────────────────────────────────────────────────┐
│                    模板+覆盖配置架构                          │
├─────────────────────────────────────────────────────────────┤
│  第一层：共享模板 (TemplateConfig)                           │
│  ├── 定义所有等级通用的配置                                  │
│  ├── 触发器、条件、行为逻辑等                                │
│  └── 作为配置的"基类"                                        │
├─────────────────────────────────────────────────────────────┤
│  第二层：等级覆盖 (LevelOverride)                            │
│  ├── 只包含该等级的差异配置                                  │
│  ├── 数值调整、特效变化、特殊能力                            │
│  └── 可选的完全覆盖选项                                      │
├─────────────────────────────────────────────────────────────┤
│  第三层：运行时合并 (GetLevelConfig)                         │
│  ├── 模板 + 覆盖 → 完整配置                                 │
│  ├── 自动处理合并逻辑                                        │
│  └── 对外提供统一的配置接口                                  │
└─────────────────────────────────────────────────────────────┘
```

## 技能系统优化方案

### 当前配置结构

**问题示例**：
```
SkillConfig: "撞墙提升伤害"
├── Level 1 (完整配置)
│   ├── triggerConfig: WallCollision       ← 重复
│   ├── conditionConfig: CollisionCount=3  ← 重复
│   ├── effectConfig: DamageBoost=0.5      ← 唯一差异
│   └── resetCondition: OnNextAttack       ← 重复
│
├── Level 2 (完整配置)
│   ├── triggerConfig: WallCollision       ← 重复
│   ├── conditionConfig: CollisionCount=3  ← 重复
│   ├── effectConfig: DamageBoost=1.0      ← 唯一差异
│   └── resetCondition: OnNextAttack       ← 重复
│
└── Level 3 (完整配置)
    ├── triggerConfig: WallCollision       ← 重复
    ├── conditionConfig: CollisionCount=3  ← 重复
    ├── effectConfig: DamageBoost=1.5      ← 唯一差异
    └── resetCondition: OnNextAttack       ← 重复

配置项总数：3级 × 4项 = 12项配置
重复配置：9项（75%）
```

### 优化后配置结构

**优化示例**：
```
SkillConfig: "撞墙提升伤害"
├── 共享模板 (SkillTemplateConfig)
│   ├── triggerConfig: WallCollision       ← 配置一次
│   ├── conditionConfig: CollisionCount=3  ← 配置一次
│   └── resetCondition: OnNextAttack       ← 配置一次
│
└── 等级覆盖列表 (SkillLevelOverride)
    ├── Level 1: effectConfig=0.5          ← 只配置差异
    ├── Level 2: effectConfig=1.0          ← 只配置差异
    └── Level 3: effectConfig=1.5          ← 只配置差异

配置项总数：3项模板 + 3项差异 = 6项配置
配置量减少：50%
```

### 配置组成部分

#### 1. 共享模板配置
**包含内容**：
- 触发器配置（TriggerConfig）
- 触发条件配置（ConditionConfig）
- 重置条件配置（ResetConditionConfig）
- 效果移除配置（EffectRemovalConfig）

**特点**：
- 配置一次，所有等级共享
- 修改模板，所有等级生效
- 减少重复配置工作

#### 2. 等级覆盖配置
**包含内容**：
- 等级编号和描述
- 效果配置（SkillEffectConfig）- 必填
- 可选的条件覆盖
- 可选的重置条件覆盖
- 可选的特殊配置

**特点**：
- 只配置与模板不同的部分
- 支持完全覆盖或增量调整
- 灵活性与简洁性平衡

### 配置覆盖策略

#### 策略A：仅差异覆盖（推荐）
- 大部分配置使用模板
- 只覆盖必须不同的部分（如效果数值）
- 适合等级间差异小的技能

#### 策略B：选择性覆盖
- 某些等级需要特殊逻辑
- 通过 Override 标志选择性覆盖
- 适合高等级有特殊机制的技能

#### 策略C：完全覆盖
- 某个等级完全不同
- 提供完整的独立配置
- 作为特殊情况的退路

        ├── levelName: "骷髅王"

### 配置组成部分

#### 1. 敌人类配置（EnemyClass）
**包含内容**：
- 类名称和基础信息
- 共享的预制体引用
- 移动类型和攻击类型
- AI 行为配置
- 显示信息（EnemyInfo）

**特点**：
- 一个敌人类型一个 SO
- 包含该类型的所有层级
- 便于批量调整

#### 2. 层级配置（EnemyLevelConfig）
**包含内容**：
- 层级编号和名称
- 属性数值（血量、伤害、速度）
- 视觉差异（Sprite、颜色）
- 特殊能力（高层级专属）

**特点**：
- 在 EnemyClass 中以列表形式存在
- 每个层级独立配置数值
- 支持视觉和能力差异化

### 层级差异化策略

#### 策略A：纯数值递增
- 只改变属性数值
- 外观和行为完全相同
- 适合：普通怪 → 精英怪

#### 策略B：数值+视觉差异
- 数值递增 + 外观变化
- Sprite、颜色、特效不同
- 适合：需要视觉区分的层级

#### 策略C：数值+能力差异
- 数值递增 + 新增特殊能力
- Boss 级别专属技能
- 适合：普通怪 → Boss

## 运行时处理机制

### 配置合并逻辑

#### 合并优先级
```
1. 从模板读取基础配置
2. 检查等级覆盖配置
3. 如果有覆盖，使用覆盖值
4. 如果无覆盖，使用模板值
5. 生成完整的运行时配置
```

#### 合并时机
- **初始化时**：技能学习时、敌人生成时
- **升级时**：技能升级时重新合并
- **运行时**：配置不变，只读取

### 实例化策略

#### 技能实例化
```
玩家学习技能 → 指定等级 → 合并配置 → 创建 SkillInstance
├─ SkillConfig（模板 SO）
├─ Level（等级参数）
└─ SkillInstance（运行时实例）
```

#### 敌人实例化
```
生成敌人 → 指定层级 → 合并配置 → 创建 EnemyStats
├─ EnemyClass（模板 SO）
├─ Tier（层级参数）
└─ EnemyStats（运行时组件）
```

## 最佳实践

### 配置设计建议

#### 模板配置原则
1. **只包含真正共享的部分**
   - 不要把所有配置都放模板
   - 如果某配置各等级都不同，不要放模板

2. **模板应该稳定**
   - 模板改变影响所有等级
   - 谨慎修改模板配置
   - 充分测试模板变更

3. **提供合理默认值**
   - 模板应包含完整配置
   - 默认值应该可用
   - 避免必须覆盖的配置

#### 覆盖配置原则
1. **只配置差异**
   - 不要重复配置模板已有的
   - 明确标识哪些是覆盖
   - 保持覆盖配置简洁

2. **使用增量配置**
   - 优先使用倍率而非绝对值
   - 例如：伤害 ×1.5 而非 = 15
   - 便于整体平衡调整

3. **特殊情况明确标注**
   - 完全覆盖时添加注释
   - 说明覆盖原因
   - 便于后期维护

### 命名规范

#### 技能配置
```
SkillConfig: "技能名称"
├─ template: "共享逻辑"
└─ levelOverrides:
    ├─ Level 1: "基础效果"
    ├─ Level 2: "增强效果"
    └─ Level 3: "终极效果"
```

#### 敌人配置
```
EnemyClass: "敌人类型名"
├─ sharedConfig: "共享行为"
└─ tiers:
    ├─ Tier 1: "类型名_普通"
    ├─ Tier 2: "类型名_精英"
    └─ Tier 3: "类型名_Boss"
```

## 总结

### 核心价值

本方案通过引入"模板+覆盖"配置模式，实现：

1. **配置效率提升**
   - 消除重复配置
   - 集中管理共享逻辑
   - 简化配置流程

2. **维护成本降低**
   - 修改一次，全局生效
   - 保证配置一致性
   - 减少人为错误

3. **可扩展性增强**
   - 新增等级/层级更简单
   - 支持灵活的差异化配置
   - 保持架构清晰

4. **团队协作改善**
   - 配置结构清晰易懂
   - 降低学习成本
   - 提升开发效率

### 适用场景

**推荐使用**：
- ✅ 技能多等级系统
- ✅ 敌人多层级系统
- ✅ 任何有"基础+变体"的配置
- ✅ 需要大量重复配置的系统

**不推荐使用**：
- ❌ 等级间差异巨大（完全不同）
- ❌ 只有 1-2 个等级
- ❌ 配置极其简单的系统
