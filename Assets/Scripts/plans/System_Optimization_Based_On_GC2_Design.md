# 基于 Game Creator 2 设计思路的系统优化清单

## 文档信息
- **创建日期**: 2024年12月
- **版本**: 1.0
- **状态**: 规划阶段
- **目标**: 借鉴 GC2 的优秀设计模式优化现有系统

---

## 概述

本文档总结了通过分析 Game Creator 2 插件后，发现的8个可以应用到我们项目中的优秀设计模式。这些优化方向不会改变现有系统的核心架构，而是通过引入更好的设计模式来提升代码质量、可维护性和扩展性。

**核心原则**：
- ✅ 保持现有系统的核心优势
- ✅ 借鉴设计思路，不照搬代码
- ✅ 分阶段实施，充分测试
- ✅ 提升开发效率和可维护性

---

## 优化项清单

### 1. 配置系统多态化 ⭐⭐⭐⭐⭐

**优先级**: 最高  
**难度**: 中等  
**收益**: 极高  
**推荐指数**: ⭐⭐⭐⭐⭐

#### 当前问题
- 使用 `enum + switch` 模式创建实例
- 所有类型的参数混在同一个配置类中
- 需要使用 `ShowIf` 隐藏不相关参数
- 新增类型需要修改多处代码
- Inspector 显示冗余字段

#### GC2 的设计思路
- 使用 `SerializeReference` 实现多态序列化
- 每个类型只包含自己的参数
- 通过抽象基类统一接口
- 使用类型选择器动态选择实现

#### 优化方向
- **TriggerConfig 多态化**
  - 创建 `TriggerBase` 抽象类
  - 每个触发器继承基类，只包含自己的参数
  - 使用 `[SerializeReference]` 和 `[TypeSelector]`

- **ConditionConfig 多态化**
  - 创建 `ConditionBase` 抽象类
  - 简化复合条件的配置方式
  - 每个条件独立配置

- **EffectConfig 多态化**
  - 创建 `EffectBase` 抽象类
  - 效果参数完全独立
  - 支持效果嵌套和组合

#### 预期收益
- ✅ Inspector 体验显著提升（只显示相关参数）
- ✅ 代码扩展性极大增强（符合开闭原则）
- ✅ 类型安全性提升（编译时检查）
- ✅ 减少配置错误（无冗余参数）

#### 实施建议
1. 先创建抽象基类
2. 逐步迁移现有实现类
3. 编写数据迁移工具
4. 充分测试后替换旧系统

---

### 2. Args 参数传递系统 ⭐⭐⭐⭐

**优先级**: 高  
**难度**: 低  
**收益**: 高  
**推荐指数**: ⭐⭐⭐⭐

#### 当前问题
- 直接传递 `object` 类型的事件数据
- 每次都需要类型转换
- 无类型安全保障
- 重复的 GetComponent 调用

#### GC2 的设计思路
- 统一的 `Args` 参数容器
- 包含事件发起者和目标对象
- 内置组件缓存机制
- 提供类型安全的访问方法

#### 优化方向
- 创建 `SkillArgs` 统一参数类
  - 包含 Source 和 Target 对象
  - 支持多种事件数据（AttackData, DeathData 等）
  - 内置组件缓存，避免重复查找
  - 提供类型安全的访问接口

- 统一所有接口签名
  - ITrigger.CheckEvent(SkillArgs args)
  - ICondition.CheckCondition(SkillArgs args)
  - IEffect.ExecuteEffect(SkillArgs args)

#### 预期收益
- ✅ 类型安全（无需手动类型转换）
- ✅ 性能提升（组件缓存）
- ✅ 代码可读性增强
- ✅ 更好的 IDE 支持

#### 实施建议
1. 创建 SkillArgs 类
2. 更新所有接口定义
3. 逐步迁移现有实现
4. 保留兼容适配器（过渡期）

---

### 3. Property 动态值系统 ⭐⭐⭐⭐

**优先级**: 高  
**难度**: 中等  
**收益**: 高  
**推荐指数**: ⭐⭐⭐⭐

#### 当前问题
- 技能配置中只能使用固定值
- 无法配置动态计算的值
- 缺少灵活性

#### GC2 的设计思路
- Property 系统支持多种值来源
- 可以是固定值、变量、随机数、计算结果
- 运行时动态获取
- 支持复杂的值表达式

#### 优化方向
- 创建 `DynamicFloat` / `DynamicInt` 等动态值类型
- 支持多种值提供者：
  - 固定值
  - 随机范围
  - 基于血量百分比
  - 基于技能等级
  - 从变量读取
  - 数学表达式计算

#### 预期收益
- ✅ 技能配置更灵活
- ✅ 支持更复杂的机制
- ✅ 减少硬编码
- ✅ 易于平衡调整

#### 应用场景
- 伤害倍率随血量变化
- 技能范围随等级增长
- 随机效果数值
- 基于玩家属性的计算

#### 实施建议
1. 先实现 DynamicFloat 基础框架
2. 添加常用的值提供者
3. 在技能配置中逐步替换固定值
4. 根据需要扩展更多提供者

---

### 4. 异步系统统一化 ⭐⭐⭐

**优先级**: 中  
**难度**: 中等  
**收益**: 中  
**推荐指数**: ⭐⭐⭐

#### 当前问题
- 同时使用协程和同步调用
- 异步处理不统一
- 难以编写复杂的异步逻辑

#### GC2 的设计思路
- 全面采用 `async/await` 模式
- 提供统一的异步辅助方法
- 所有 Instruction 返回 Task
- 清晰的异步控制流

#### 优化方向
- 为技能效果添加异步支持
- 统一使用 Task 而非协程
- 提供异步辅助方法：
  - WaitForSeconds
  - WaitUntil
  - WaitWhile
- 支持效果链式执行

#### 预期收益
- ✅ 异步逻辑更清晰
- ✅ 更好的异常处理
- ✅ 支持复杂的时序控制
- ✅ 现代化的异步模式

#### 实施建议
1. 为 IEffect 添加异步版本接口
2. 创建异步辅助方法基类
3. 逐步迁移需要异步的效果
4. 保持同步接口作为简化版本

---

### 5. Manager 单例模式统一 ⭐⭐⭐

**优先级**: 中  
**难度**: 低  
**收益**: 中  
**推荐指数**: ⭐⭐⭐

#### 当前问题
- 每个 Manager 都重复实现单例逻辑
- 代码冗余
- 容易出错（忘记 DontDestroyOnLoad 等）

#### GC2 的设计思路
- 使用泛型基类 `Singleton<T>`
- 统一的生命周期管理
- 提供 OnCreate/OnDestroy 虚方法
- 处理应用退出情况

#### 优化方向
- 创建 `SingletonManager<T>` 基类
- 所有 Manager 继承该基类
- 统一处理：
  - 实例创建和销毁
  - DontDestroyOnLoad
  - 重复实例检测
  - 应用退出处理

#### 预期收益
- ✅ 消除代码重复
- ✅ 统一的生命周期管理
- ✅ 减少出错可能
- ✅ 更清晰的 Manager 结构

#### 适用范围
- SkillManager
- WeakPointManager
- EffectManager
- 所有全局单例管理器

#### 实施建议
1. 创建 SingletonManager<T> 基类
2. 从最简单的 Manager 开始迁移
3. 测试确保行为一致
4. 逐步迁移所有 Manager

---

### 6. 事件系统优先级增强 ⭐⭐⭐

**优先级**: 中  
**难度**: 低  
**收益**: 中  
**推荐指数**: ⭐⭐⭐

#### 当前状态
- 已定义 EventPriority 枚举
- IDamageModifier 已使用优先级
- GameEventBus 未使用优先级排序

#### GC2 的设计思路
- 事件订阅者可以指定优先级
- 按优先级顺序执行回调
- 高优先级可以拦截或修改事件

#### 优化方向
- 创建 `PriorityEventManager<T>` 类
- 为每个事件维护优先级订阅列表
- 订阅时可指定：
  - 优先级等级
  - 订阅者名称（调试用）
- 发布时按优先级顺序执行

#### 预期收益
- ✅ 确保关键逻辑优先执行
- ✅ 更可控的事件处理流程
- ✅ 便于调试（知道执行顺序）
- ✅ 支持事件拦截机制

#### 应用场景
- 伤害计算流程
- 技能触发顺序
- 状态效果应用
- UI 更新时机

#### 实施建议
1. 创建 PriorityEventManager 类
2. 在新事件中试用
3. 确认效果后扩展到所有事件
4. 为关键事件标注优先级需求

---

### 7. ScriptableObject Repository 模式 ⭐⭐

**优先级**: 低  
**难度**: 低  
**收益**: 低  
**推荐指数**: ⭐⭐

#### 当前问题
- 技能配置通过遍历查找
- 没有统一的配置入口
- 缺少缓存机制

#### GC2 的设计思路
- 使用 Repository 模式集中管理配置
- 构建字典缓存，O(1) 查找
- 支持多种查询方式（ID、标签、类型）

#### 优化方向
- 创建 `SkillRepository` 单一资源
- 包含所有技能配置引用
- 运行时构建缓存字典：
  - 按名称查找
  - 按标签分组
  - 按角色筛选

#### 预期收益
- ✅ 查找性能提升（O(n) → O(1)）
- ✅ 统一的配置入口
- ✅ 便于管理和组织
- ✅ 支持更复杂的查询

#### 实施建议
1. 创建 SkillRepository ScriptableObject
2. 迁移现有技能引用
3. 添加缓存构建逻辑
4. 更新 SkillManager 使用 Repository
